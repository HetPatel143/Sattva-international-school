Modernization Brief · Not Yet Implemented

Sattva, reconsidered: from Heritage to New Classic

A plan to move Sattva's visual identity forward — more advanced, more trustworthy, still unmistakably a serious school — by borrowing proven structural ideas from Arpanam's build, never its playful colour or preschool register. This is a list to review, not a diff to merge.

Direction · New Classic Keep · Playfair + gold heritage cue Shift · umber → navy, sharp → refined Source · Arpanam's systems, not its palette

00 The Direction

What "new classic, trustworthy" means here

Sattva's current look — warm umber brown, sharp 2px corners, Playfair Display in heavy uppercase — reads as heritage: dignified, a little old-world. The brief is to keep the dignity and lose the "old" — swap warm-brown for a cooler, more institutional navy; keep the gold but refine it; keep the serif but stop shouting in uppercase; and let elevation and motion do more of the "advanced" work, the way Arpanam's brand-tinted shadows and choreographed reveals do. The result should look like a school that modernized deliberately, not one that lost its identity.

01 Palette Shift

Warm umber → institutional navy, gold refined

The gold stays — it's the one irreplaceable link to the logo and to "heritage." Everything around it cools down: brown becomes navy (the colour of banks, universities, and law firms — the universal shorthand for "trustworthy"), and the cream ground gets slightly cooler so the gold reads as an accent, not a match.

Logo mark stays untouched: the crimson (#C7414A → nudge to #A23B42 for weight) and the green/purple/blue "tile" icon colours keep doing exactly what they do now — decorate icons only. Only the dominant, structural colour changes.

02 Typography

Same serif, quieter voice

Keep

  • Playfair Display for every headline — it's the single strongest "trustworthy institution" signal already in place.
  • Italic serif subtitles for legend-quote banners — a genuine voice, don't lose it.

Refine

  • Drop the hero from uppercase + 4px tracking to sentence case — monumental-plaque energy reads dated next to a modern layout.
  • Cap hero size nearer 64px than 80px; let whitespace carry weight instead of raw scale.
  • Borrow Arpanam's discipline of one clear scale, applied consistently rather than per-page inline overrides (Contact.jsx currently sets font sizes via inline style=).

03 Shape & Elevation

Soften the corners, add brand-tinted depth

Radius: 2–4px → 8–10px

Fully sharp corners read as stern/old-world. A modest 8–10px radius (never a pill — that would tip into Arpanam's playful register) reads as considered and current without losing formality.

now: 2px
new: 9px

Elevation: neutral → brass-tinted

This is Arpanam's single best trick, ported to Sattva's palette: shadows mixed from the brand colour instead of flat black. It's the fastest way to make a card feel "advanced" rather than "flat."

04 What to Take from Arpanam

Ten specific things — each adapted to New Classic, not copied

Priority tags: Phase 1quick, high-leverage · Phase 2meaningful build · Phase 3larger investment.

1

A reusable page-hero component

Phase 1

Arpanam has one PageHero component every interior page calls with different props. Sattva hand-writes the page-header JSX block fresh in every page file (confirmed in Gallery.jsx and Contact.jsx) — same markup, copy-pasted five times.

Adapt: extract a <PageHeader title subtitle image emphasis /> component in navy-and-brass styling; every page shrinks to a one-line call, and future header changes happen once.
2

Field-level form validation

Phase 1

Arpanam's contact form sanitises input live and shows a per-field error tied via aria-describedby/aria-invalid. Sattva's Contact.jsx relies only on native required plus one global error banner — a user who mistypes an email only finds out after submitting.

Adapt: add per-field validation (email format, phone digits) with an inline message under the underline input, in the same navy-on-crimson error colour already defined for --color-accent.
3

A persistent mobile conversion bar

Phase 1

Arpanam keeps a sticky bottom bar (Call / Admissions) visible on mobile at all times. Sattva's only mobile CTA lives inside the hamburger drawer — once closed, there's no persistent "Apply Now" affordance while scrolling.

Adapt: a slim fixed bottom bar in navy with a brass-outline "Apply Now" and a phone icon, matching the drawer's existing colour logic (cream when scrolled, dark over hero).
4

Scroll-triggered reveal, not mount-only fade

Phase 2

Arpanam's Reveal component uses whileInView — content animates in as the user scrolls to it. Sattva's animate-fade-in + delay-100/200/300 classes fire once on page mount, so anything below the fold has already "finished animating" before it's ever seen.

Adapt: swap the CSS keyframe approach for a small IntersectionObserver hook (no need for Framer Motion — React 19 + a 20-line hook is enough) that adds the existing .animate-fade-in class when a section enters the viewport.
5

An interactive testimonial slider

Phase 2

Arpanam's testimonials are a real slider — prev/next controls, star ratings, one quote in focus at a time. Sattva's testimonial section is a static grid that only becomes a swipe carousel below 768px, with no way to browse more than what's visible on desktop.

Adapt: add prev/next arrow buttons (already have the icon set via lucide-react) to cycle one testimonial-card at a time on desktop, styled in navy/brass — keep the existing card design entirely, just add navigation.
6

A wider, systemized button vocabulary

Phase 2

Arpanam ships 7 named button variants for different weights of action. Sattva has two: .btn-primary and .btn-outline — every CTA on the site is one of these two, regardless of how important it actually is.

Adapt: add a .btn-ghost (text-only, navy, for in-card links like "Read More") and a .btn-subtle (soft brass-tinted background, for secondary-but-not-throwaway actions) — two additions, not seven, since Sattva's simpler action model doesn't need Arpanam's full range.
7

Named, reusable elevation tokens

Phase 2

Arpanam defines shadow-soft / shadow-glow / shadow-card once in its Tailwind config and reuses them everywhere. Sattva already has a shadow scale (--shadow-sm through --shadow-xl) but it's neutral-black only — this pairs directly with item 03 above.

Adapt: add --shadow-brass and --shadow-navy custom properties alongside the existing neutral scale, and reach for them specifically on hover states and hero CTAs.
8

Responsive images with reserved space

Phase 3

Arpanam gets this for free from next/image (auto width/height, no layout shift). Sattva hand-writes srcSet/sizes correctly, but images have no reserved aspect-ratio, so slow connections see visible layout jump as gallery/hero images load in.

Adapt: add aspect-ratio to .gallery-item, .hero-image, and .news-image-wrapper containers so space is reserved before the image arrives.
9

Retint the icon "tile" colours to the new palette

Phase 3

Not literally from Arpanam, but the same principle Arpanam applies (decoration hues stay contained and coherent): Sattva's tile-green/purple/blue icon backgrounds were tuned against warm umber — against navy they'll read colder and slightly mismatched.

Adapt: shift each tile hue slightly cooler/deeper to sit comfortably next to navy — same logo-derived hues, retuned for the new ground, not replaced.
10

Consolidate inline styles into the token system

Phase 3

Arpanam's Tailwind config means every spacing/colour/radius decision routes through one file. Sattva's CSS custom properties do the same in principle, but several pages (e.g. Contact.jsx's style={{ fontSize: '2rem' }}) bypass the token system with inline overrides.

Adapt: sweep inline style= props back into the relevant .css files as real classes — makes the new navy/brass rollout a find-and-replace instead of a page-by-page hunt.

05 Protect These

Where Sattva is already ahead of Arpanam

Modernizing shouldn't mean regressing. Three things Sattva already does better — don't let a redesign accidentally lose them.

Global accessibility guard: the site-wide *:focus-visible ring and prefers-reduced-motion block in index.css are stronger defaults than Arpanam has today. Keep them exactly as they are through the redesign.

Gallery keyboard + touch support: arrow-key navigation, Escape, a real focus trap, and swipe gestures in the lightbox. Restyle the chrome, never the interaction logic.

Async form submission with real feedback: the spinner-then-checkmark success state on Contact/Admissions is already the interaction pattern Arpanam is missing. Only add validation on top of it — don't replace it.

06 Suggested Sequence

Three phases, not one big rewrite

1

Palette + quick wins

Swap the umber/gold/cream tokens for navy/brass/paper across index.css; add the page-hero component, sticky mobile CTA, and per-field form validation. This alone changes the site's temperature without touching layout.

2

Interaction depth

Scroll-triggered reveals, the testimonial slider, expanded button set, and brass/navy elevation tokens — the site starts to feel as advanced as it now looks.

3

Polish & consolidation

Image aspect-ratio boxes, retinted icon tiles, and sweeping inline styles back into the token system — the maintainability pass that makes future changes cheap.
